# Conventions for this workspace

Rules learned from the way Site Studio actually imports code. `README.md` is
regenerated by every **Push Site → GitHub**, so project conventions live here
instead.

## No backslashes in runtime code

**A backslash written anywhere in `runtime/` never reaches the live site.**

Site Studio's importer stores snippet and canvas code with `update_post_meta()`,
and the WordPress meta API unslashes whatever it is given. One level of
backslashes is removed on the way into the database:

| written in the repository | what the site actually runs |
| --- | --- |
| `"\n"` | `"n"` — a literal letter n |
| `'/\s+/u'` | `/s+/u` — matches the letter s, not whitespace |
| `'piece\'s'` | `'piece's'` — a PHP syntax error |

The snippet validator runs against the *file*, so a broken snippet passes import
and only fails when it executes. The plugin then disables it and the feature
silently disappears.

None of the seven original production snippets contains a single backslash. Keep
it that way. The workarounds are straightforward:

| instead of | write |
| --- | --- |
| `"\n"`, `"\t"` | `chr( 10 )`, `chr( 9 )` |
| `\s`, `\d`, `\.` in a regex | `[[:space:]]`, `[[:digit:]]`, `[.]` |
| `'it\'s'` | `"it's"` |
| an escape inside inline JavaScript | build it at runtime, e.g. pass the real characters from PHP with `chr()` and assemble the regex with `new RegExp()` |

Backslashes are fine in strings *produced* at runtime — only the source stored in
this repository is affected. `ioulia_php_literal()` in the i18n editor snippet
shows the pattern for emitting code that has to survive a round trip.

## Check before committing

```
docker run --rm -v "$PWD":/w -w /w php:8.2-cli php tools/check-import.php
```

It reports any snippet whose code changes under the importer's unslashing, and
parses the result the same way the plugin's validator does.

## Deploying

A Git push changes nothing on its own. An administrator must run
**Site Sync → Pull GitHub → Site**, and the branch must be the one configured in
Site Studio (`main` by default; the pull is `--ff-only`).

Never run **Push Site → GitHub** while the repository holds work the database
does not: it exports the current database over `runtime/` and would revert it.
